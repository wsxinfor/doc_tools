二、合同审核AI

项目背景

交通部规划研究院内部使用的合同审核工具，Web访问，Docker部署在Linux服务器。 审核人员上传合同后，AI自动完成三类审核任务：

1. 单独审核：检查合同是否有明显不合理、不合规、不一致的地方

2. 主分包对比：检查分包合同条款是否与主合同形成有效&quot;条款下移&quot;，即主合同中我方承担的义务和风险，是否在分包合同中对等地转移给了分包商

3. OA截图对比：核查OA系统截图中的合同基本信息与合同原文是否一致

我方单位默认：交通部规划研究院（用户可在模板中修改）

法律依据：《中华人民共和国民法典》合同编（不是旧的合同法）

前端页面

核心设计原则

1. 模型配置完全走数据库，不硬编码

2. LLM调用走统一入口 只通过 llm_client.py 调用任何模型。 统一用OpenAI兼容接口，Ollama和外部API都走这个格式。 禁止在其他文件直接发HTTP请求给模型。

3. Prompt两层结构，组装在后端

系统固定层（代码里，用户不可见）

└── 角色定义、输出格式要求、法律依据

用户模板层（数据库里，用户完全可编辑）

└── 我方单位、审核要点、特殊规则

所有Prompt组装逻辑集中在 prompt_builder.py。 禁止在其他文件拼接Prompt字符串。

4. 关键条款对比分两类处理

纯数值字段（金额比例等）：代码计算，结果作为上下文注入Prompt

语义理解类条款（日期、违约、付款、质量、争议解决等）：模型负责对比 禁止把语义理解类的对比写成硬编码规则，那是模型该做的事。

5. 三条审核路径严格独立 单独审核、主分包对比、OA截图对比是三条完全独立的路径， 不要试图合并成一个通用流程。

审核路径说明

路径1：单独评审

上传主合同

→ PDF解析提取文本（文字版）

→ 选择模板

→ prompt_builder 组装完整Prompt

→ 调用文本模型审核

→ 输出：总体评估 / 发现问题 / 修改建议 / 风险条款 / 审查总结

→ 导出Word/PDF

路径2：主分包对比

核心逻辑：检查分包合同是否与主合同形成有效的&quot;条款下移&quot;。 即主合同中我方承担的义务和风险，是否在分包合同中对等地转移给了分包商。

上传主合同 + 分包合同

→ 分别提取文本

→ ==代码计算：分包金额是否超主合同50%（结果注入Prompt）==

→ 模型重点检查以下条款的互逆性：

工期：分包完成时间是否早于主合同交付时间（留出缓冲）

违约：违约条款比例和触发条件是否对等转移给分包商

付款：付款节点是否合理（不能分包款早于收到主合同款）

质量：质量标准和验收要求是否一致传导

再分包：是否明确禁止分包商再次分包

争议解决：管辖机构和方式是否一致

用户模板里指定的其他条款

→ 输出：

每条关键条款：主合同原文 vs 分包合同原文 vs 是否有效下移

风险项：标注&quot;风险留在我方&quot;的条款

缺失项：主合同有要求但分包合同完全未提及的条款

→ 导出Word/PDF

路径3：OA截图对比

上传主合同 + OA截图

→ 提取合同文本

→ 视觉模型识别截图，输出结构化JSON字段

→ 代码比对可直接比较的数值字段

→ 模型对比语义类字段（日期表述、金额描述、关键条款）

→ 输出：字段级对比清单 + 不一致项标注

→ 导出Word/PDF
