## §4 Always / Never

### Always

```
✅ 预计改动 4 个及以上文件时，先列出「文件列表+原因+顺序」，等待确认
✅ 用证据定位根因，不猜测（看日志、看报错、看测试输出）
✅ 测试全部通过后才能 git commit
✅ DDL 改动必须写迁移脚本（含 up + down）
✅ 所有外部输入做 schema 校验（API 入参、文件上传、表单）
✅ 金额计算防 NaN/null，NaN 禁止出现在 UI 或 API 响应
✅ 核心数据使用软删除，被引用数据不可硬删除
✅ 新增第三方依赖前在 docs/ADR/ 记录引入原因
✅ 日志只写到 backend/logs/，文件名带项目前缀
```

### Never

```
❌ 测试未通过时 git commit
❌ AI 结果绕过用户确认直接写库
❌ 业务代码直接 import AI SDK（必须通过 adapter 层）
❌ TypeScript any 类型（必须时在行尾注释原因）
❌ 生产/开发代码保留 console.log
❌ 顺手重构任务范围外的代码
❌ 同一 commit 混合多个模块改动
❌ 自动执行 git push
❌ 一次性读入所有 CLAUDE.md 文件
❌ 将日志、临时文件写到项目目录之外
❌ 使用已被其他项目占用的端口（查 ~/.config/dev-ports.md）
```

## §5 Git 规范

**单人项目，无需 PR，直接 merge。**

**Commit 格式**：`类型(模块): 描述`
类型：`feat` / `fix` / `test` / `refactor` / `chore` / `docs`

**分支策略**：
- `main`：稳定版本，每个模块完成后 merge
- `dev`：日常开发
- `hotfix/*`：从 main 拉出，修完 merge 回 main + dev

**模块提交节奏**（每模块按此顺序）：
1. `feat(模块): 数据库迁移`
2. `feat(模块): 后端 API`
3. `test(模块): API 集成测试`
4. `feat(模块): 前端页面`
5. `test(模块): E2E 测试`

## §6 测试规范

**三层结构**：

```
backend/tests/unit/      # 纯函数，无 I/O
backend/tests/api/       # Supertest，测 HTTP 接口
backend/tests/fixtures/  # 种子数据，每用例独立 setup/teardown
frontend/tests/e2e/      # Playwright
```

**测试门禁（按序，全部通过才能 commit）**：

```bash
npx tsc --noEmit          # 类型检查
npm run lint              # ESLint
npm run test:unit         # 单元测试
npm run test:api          # 接口测试（使用 .env.test + 测试库端口）
npm run test:e2e          # E2E（使用测试端口）
```

**数据隔离**：测试使用 `DATABASE_URL_TEST`（见端口表测试端口），与开发库严格分离。

**E2E 必须覆盖**：新建 / 编辑 / 删除（含确认框）/ 表单校验 / 异常提示 / 页面跳转

**覆盖率要求**：金额、状态机等核心逻辑 ≥ 80%；其他模块关键路径必须有用例。

## §7 核心数据模型

所有模型必须继承软删除字段：

```typescript
// TypeScript / Prisma
interface BaseModel {
  id: string;           // UUID
  isDeleted: boolean;   // 默认 false，查询默认过滤
  createdAt: Date;
  updatedAt: Date;
}
```

**迁移命名**：`{timestamp}_{snake_case描述}`，如 `20240601_add_user_role`
**每个迁移必须实现 up + down，down 不可留空。**

## §8 开发规范

**环境变量**：
- 启动时校验所有必要 env，缺失则报错中止
- `.env.example` 与 `.env` 字段保持同步（值可为空）
- 测试用独立 `.env.test`，不与开发 env 混用

**日志**：
- 输出到 `backend/logs/{{PROJECT_NAME}}-{date}.log`
- 级别：debug / info / warn / error
- 请求格式：`[METHOD] /path → status Xms`
- catch 块必须记录 error 对象，禁止吞掉异常

**错误响应格式**：
```json
{ "code": "SNAKE_CASE_CODE", "message": "用户可读信息", "detail": {} }
```

**安全**：
- 入参用 Zod 校验
- 文件上传：类型白名单 + 大小上限
- API 加速率限制
- 认证用 JWT，密钥从 env 读取

**TypeScript**：`"strict": true`，禁用 any（必须使用时在行尾注释原因）。

## §9 AI 功能规范（无 AI 功能时删除本节）

```typescript
// backend/src/adapters/ai.adapter.ts
interface AIAdapter {
  recognize(input: string | Buffer): Promise<AIResult>;
}
interface AIResult {
  success: boolean;
  data?: unknown;
  confidence?: number;
  error?: string;
}
```

- AI 结果必须经用户确认后才能写库，禁止自动入库
- AI 接口必须加速率限制
- 失败降级提示：「识别未成功，请手动填写」
- E2E 必须覆盖：调用 → 展示结果 → 用户确认 → 写入

## §10 Bug 修复流程

```
1. 看日志/报错定位根因（不猜）
2. 确认影响范围（哪些模块、哪些接口）
3. 最小改动修复（不顺手重构）
4. 补充能复现该 Bug 的测试用例
5. 测试全部通过后提交：fix(模块): 描述
```

### 高风险操作（改动前必须口头确认）

| 操作 | 检查项 |
|------|--------|
| 修改核心表结构 | 软删除逻辑 + 外键引用完整性 |
| 修改金额/状态机计算 | 跑完该模块所有相关测试 |
| 修改 AI 调用逻辑 | E2E 重跑，确认确认流程未被绕过 |
| 修改认证中间件 | 检查所有受保护路由 |
| 修改 docker-compose 端口 | 同步更新 ~/.config/dev-ports.md |
